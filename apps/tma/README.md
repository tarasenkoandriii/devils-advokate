# apps/tma — Telegram Mini App

**Статус: MVP v1 завершён — все 13 фич реализованы**, включая деплой на Vercel Hobby (см. `../../VERCEL.md`). **MVP v2 — UI для Conversation Dossier и Commitment Tracker (первая из 11 фич §3.49-3.60) добавлен.**

## Флоу

`AppGate` (корневой layout) → дисклеймер (если не подтверждён) → главная страница → согласие на внешний AI → форма дилеммы → генерация аргументов → история проектов → карточка разговора (Decision Objective, BATNA/WATNA, аргументы, скрипты открытия/закрытия) → Steelman по фигурантам → **Досье разговора** (загрузка файла → расшифровка+диаризация → просмотр по репликам) → **Обязательства** (кто что пообещал, отметка выполнения, просрочка) → Privacy Center (согласия, персоны, TTL-политики, онбординг, журнал Safe Share, экспорт данных).

## Структура

- `src/lib/telegram.ts` — обёртка над Telegram WebApp SDK: initData, MainButton, BackButton, HapticFeedback, тема, шаринг через `t.me/share/url`, DEV bypass
- `src/lib/api.ts` — клиентская половина `apiReq`/`handle()`
- `src/lib/features.ts` — все API-вызовы (consent, projects, arguments, ai-engines, objective, boundaries, people, steelman, scripts, card, privacy, safe-share, retention-classes, onboarding, disclaimer, conversations, **commitments**)
- `src/hooks/useMainButton.ts`, `useBackButton.ts` — с честным fallback на HTML вне Telegram (`isTelegramAvailable`)
- `src/components/AppGate.tsx` (в `app/layout.tsx`) — единственная точка блокировки дисклеймера для всего дерева страниц
- `src/components/LaunchDisclaimer.tsx`, `ConsentGate.tsx`, `DilemmaForm.tsx`, `EngineSelector.tsx`, `ArgumentsList.tsx`, `ShareButton.tsx` (с полным Safe Share preflight/preview/confirm-флоу), `DecisionObjectiveForm.tsx`, `NegotiationBoundariesForm.tsx`, `PeopleSection.tsx` (список фигурантов + генерация Steelman), `OnboardingForm.tsx` (вероисповедание/город, дефолт «не указывать»), `ConversationsSection.tsx` (загрузка разговора, статус расшифровки, просмотр по репликам с указанием спикера), **`CommitmentsSection.tsx`** (список обязательств по проекту, чекбокс выполнения, просрочка подсвечивается)
- `src/app/page.tsx` — главный флоу
- `src/app/projects/`, `src/app/projects/[id]/`, `src/app/projects/[id]/card/` — история, детали проекта (включая Досье разговора и Обязательства), карточка разговора
- `src/app/privacy/` — Privacy Center: согласия, персоны с необратимым удалением, TTL-политики, онбординг, журнал Safe Share, экспорт

## Досье разговора (Conversation Dossier) — что реализовано, что нет

Поток: выбор типа источника (аудио/видео/скриншот) → выбор файла (нативный `<input type="file">`, без встроенной записи через `MediaRecorder` — поддержка захвата аудио в Telegram WebView нестабильна между платформами, **честно не реализовано, не притворяемся**) → потоковая загрузка напрямую в AssemblyAI (файл никогда не касается нашего сервера, `File`-объект передаётся в `fetch()` напрямую как тело запроса) → запуск расшифровки → polling статуса каждые 5с, пока `TRANSCRIBING` → просмотр реплик по спикерам.

**Не реализовано в этом проходе (бэкенд уже поддерживает)**:
- Сопоставление диаризационного лейбла ("A"/"B") конкретному `Person` из списка фигурантов — реплики показывают лейбл диаризации как есть, если участник ещё не сопоставлен
- Повестка следующего разговора (`ConversationAgenda`) — модель данных есть, UI нет
- Защищённые заметки / туз в рукаве / план Б (`ProtectedNote`) — модель данных есть, UI нет
- Экран согласия на `EPHEMERAL_SERVER` перед первой загрузкой — сейчас ошибка от бэкенда при отсутствии согласия просто показывается текстом в форме, нет отдельного объясняющего экрана (по аналогии с `ConsentGate.tsx` для `EXTERNAL_AI`)

## Обязательства (Commitment Tracker, §3.49 ТЗ) — что реализовано, что нет

Список + инлайн-форма добавления (кто/чьё обязательство/что именно/срок) + чекбокс отметки выполнения (снимается обратно повторным кликом) — показывает только обязательства ПО ТЕКУЩЕМУ ПРОЕКТУ (`listCommitmentsByProject`).

**Не реализовано в этом проходе (бэкенд уже поддерживает)**:
- «Хронология по фигуранту» — обязательства этого человека сразу по всем проектам (`listCommitmentsByPerson`) — бэкенд отдаёт, но в TMA нет отдельной detail-страницы персоны, куда такой список лёг бы осмысленно
- Автоматическое извлечение обязательств из разговора (постфактум-разбор транскрипта) — добавление только вручную
- Напоминания — сам планировщик (§3.20), на который ссылается эта фича в ТЗ, не существует ни в бэкенде, ни здесь

## Поворотные точки разговора (Turning Point Detection, §3.50 ТЗ)

Встроено прямо в `ConversationsSection.tsx`, не отдельный компонент — при `status=TRANSCRIBED` в развёрнутой карточке разговора появляется кнопка «Найти поворотные точки», при `status=ANALYZED` — цветные метки прямо под репликами, где детекция нашла перелом накала (⚡) или явный сдвиг позиции (🟢), с восстановленным описанием причины. Если `ARGUMENT_ACCEPTANCE` похоже на манипулятивный манёвр (совпало с `MANIPULATION_PATTERN` на том же сегменте) — рядом с меткой явная пометка «не искреннее».

## Недостающая информация (Missing Information, §3.51 ТЗ)

Отдельный компонент `MissingInformationSection.tsx`, размещён сразу под `DecisionObjectiveForm` на странице проекта — ТЗ прямо связывает эту фичу с незаполненными полями Decision Objective. Кнопка «Проверить, чего не хватает» → список уточняющих вопросов от AI (или сообщение, что ключевой информации достаточно). **Не блокирует** генерацию аргументов или другие действия на странице — отдельный необязательный AI-вызов по запросу, не жёсткий гейт (см. `apps/api/prisma/README.md`, «Пункт 16», честно зафиксированная граница реализации).

## Разрыв доказательной базы (Evidence Gap, §3.52 ТЗ)

`EvidenceGapSection.tsx`, сразу после `ArgumentsList` — разбивка уже существующих аргументов проекта по 6 категориям (🔵 Известно / 🟢 Подкреплено / 🟡 Предполагается / 🔴 Противоречиво / 🕓 Устарело / ⚪ Неизвестно). В отличие от остальных v2-фич — грузится автоматически при открытии страницы, без кнопки «запустить»: классификация не требует AI-вызова, только чтение уже существующих полей (`Argument.derivedFrom*`, `PersonFact.sourceType/status/lastVerifiedAt`).

## Что не стоит говорить (Do Not Say, §3.53 ТЗ)

Реализовано в двух местах. (1) `ConversationsSection.tsx` — кнопка «Проверить, что не стоило говорить» рядом с кнопкой поворотных точек, метки прямо на репликах пользователя (⚠️ с обоснованием риска и безопасной альтернативой формулировки). (2) Страница карточки разговора (`card/page.tsx`) — новая секция «Предупреждения из прошлых разговоров», агрегирующая AI-детекцию по ВСЕМ разговорам проекта сразу, рядом с уже существующей секцией «Не стоит упоминать» (это РУЧНОЙ список из `DecisionObjective.doNotSay` — разные источники, не смешаны в одну секцию).

## Рекомендованный следующий шаг (Best Next Move, §3.54 ТЗ)

Третья кнопка в `ConversationsSection.tsx` — «Рекомендовать следующий шаг». В отличие от поворотных точек и Do Not Say (бейджи на конкретных репликах транскрипта) — это рекомендация на весь разговор целиком, рендерится отдельным блоком из 4 карточек (лучшее действие / альтернатива / чего избегать / почему) после списка реплик, не привязана к конкретному сегменту.

**Пункт 20 (§3.55 ТЗ, «Объяснение почему не») расширил этот же блок**, не добавил новую кнопку — ещё 2 карточки («почему не альтернатива» / «что могло бы изменить рекомендацию»), визуально приглушены (пунктирная рамка) относительно основных четырёх, рендерятся только если AI их прислал.

## Разрешение конфликта источников (Source Conflict Resolver, §3.56 ТЗ)

Встроено в `PeopleSection.tsx`, не в `ConversationsSection.tsx` — фича про фигуранта в целом, не про конкретный разговор (факты о человеке могут быть из нескольких разных проектов). Кнопка «Проверить факты на противоречия» внутри развёрнутой карточки персоны → список найденных конфликтов, каждый с описанием, обоими фактами, возможными объяснениями расхождения и уточняющим вопросом, плюс кнопка «Отметить разобранным» (не «выбрать правильный факт» — система намеренно не решает, какой источник верен). Добавлена явная кнопка разворачивания карточки персоны — раньше разворачивалась только побочным эффектом генерации Steelman.

## Предупреждение об устаревших фактах (Stale Fact Alert, §3.57 ТЗ)

Реализовано в двух местах, без кнопки «проверить» в обоих — детерминированная выборка, не AI-вызов. (1) Карточка разговора (`card/page.tsx`) — новая секция «Устаревшие факты», агрегирует по всем фигурантам проекта сразу. (2) `PeopleSection.tsx` — по конкретному фигуранту, загружается сразу при разворачивании карточки персоны, рядом с уже существующими Steelman и Source Conflicts.

## Жизненный цикл аргумента (Argument Lifecycle, §3.58 ТЗ)

`ArgumentsList.tsx` стал клиентским компонентом (был серверным) — на каждом аргументе `<select>` смены статуса (черновик/проверен/использован/принят/отвергнут/опровергнут/устарел/подтверждён). При переходе именно в «отвергнут»/«опровергнут» — запрос инсайта «этот аргумент уже N раз не сработал», показывается только при достижении порога (3 раза). Оба места использования компонента (главная страница после генерации, страница проекта) обновлены под новый обязательный проп `projectId`.

## Незакрытые вопросы (Open Loops, §3.59 ТЗ)

`OpenLoopsSection.tsx` — краткая сводка сразу под заголовком проекта, первое, что видно при открытии страницы. Без AI-вызова, без кнопки «проверить» — чистая агрегация уже существующих данных (обязательства, аргументы в статусе «использован»/«опровергнут», вопросы из двух источников). Сворачиваемые детали по клику, компонент вообще не рендерится, если сводка пустая.

## Прогноз против реальности (Prediction vs Reality, §3.60 ТЗ)

`PredictionsSection.tsx` — двухфазная форма. Фаза 1: «Добавить прогноз» — фиксирует, что вы ожидаете, до того как известен результат. Фаза 2 (появляется на каждом ещё неразрешённом прогнозе): «Записать фактический результат» — после сохранения AI сравнивает прогноз с реальностью, разница и вывод показываются прямо в карточке.

## Сопоставление диаризации, повестка, защищённые заметки (раздел 2 ТЗ)

Три последних пробела «Досье разговора».

**Сопоставление диаризации** — в `ConversationsSection.tsx`, блок «Кто есть кто в записи» перед списком реплик, при развороте карточки разговора. Выпадающий список на каждого уникального участника: не сопоставлено / это я / конкретный фигурант проекта.

**Повестка следующего разговора** — на странице карточки разговора (`card/page.tsx`), кнопка «Сформировать повестку» — AI формирует список пунктов на основе цели и транскриптов последних разговоров.

**Туз в рукаве / План Б** — там же, простая форма добавления (тип + текст, без AI — по ТЗ пользователь вписывает сам) + список с кнопкой удаления. **Честно не реализовано**: проактивное напоминание «когда разговор заходит в тупик» — требует live-мониторинга, которого в проекте нет.

## Честно о проверке

`next build`/`tsc` не прогонялся ни разу за весь проект — нет сети для установки зависимостей в среде разработки. Ручная проверка на каждом проходе: баланс скобок, сверка импортов с экспортами, целевой grep на регрессии уже однажды найденных багов (`React.ReactNode` без импорта, `as any`). Для `ConversationsSection.tsx` дополнительно прогнан настоящий TypeScript-компилятор с полным контекстом `lib/`+`hooks/` (не изолированным файлом) — все найденные ошибки прослежены до отсутствия `@types/react`/`@types/node` в этой среде (нет сети для установки), не до реальных проблем в коде. Найденные и исправленные в процессе реальные ошибки — см. `../api/prisma/README.md`, там же полный список решений по каждой фиче. **Первый реальный `npm install && npm run build`/деплой на Vercel — не формальность, а первая настоящая компиляционная проверка всего фронтенда разом.**

## MVP v3 — целенаправленный заход (Пункты 36-59)

Двадцать две TMA-фичи — исходно шесть, отобранных как готовые без новой инфраструктуры (после анализа «стоит ли выполнять MVP v3 сейчас»), плюс шестнадцать доработок по прямым запросам позже (граф связей, карта круга лиц, поиск прецедентов, прогноз по сценариям, реверс-поиск фото, аргументы для примирения, планировщик, калибровка решений, критика собственной позиции, спарринг с оппонентом, публичное обсуждение (owner-side) + публичная страница, отправка в библиотеку + очередь модерации + две публичные страницы библиотеки, факты персоны + предупреждение о геометках EXIF, анализ вероятных мотивов — последняя из шести ранее не начатых фич v3-роадмапа, найденных при аудите, доводит группу до конца после явного обсуждения объёма с пользователем). Пятая доработка (аргументы для примирения) единственная потребовала сознательной отмены более раннего privacy-решения проекта, восьмая (калибровка) — единственная, где формулировка ТЗ («показывает когнитивные искажения») была намеренно переработана в реальную вычисленную статистику вместо AI-заявлений о психологии пользователя, девятая (критика собственной позиции) — единственная, где по ходу построения нашлась и была честно исправлена собственная более ранняя ошибка, десятая (спарринг) — единственная за весь заход с настоящим многоходовым чат-интерфейсом, не одноразовой генерацией, четырнадцатая (библиотека) — потребовала минимальной ролевой модели (модератор), пятнадцатая (факты + EXIF) — единственная с рукописным бинарным парсером (JPEG/EXIF), проверенным на настоящих синтетических байтах, шестнадцатая (мотивы) — единственная, где половина ТЗ (публичный поиск по имущественным реестрам) сознательно отклонена по этическим соображениям, реализована только генерация гипотез поверх уже накопленных личных данных.

Первые две интегрированы в `ConversationsSection.tsx`, тот же паттерн, что Turning Points/Do Not Say: бейдж на реплике + отдельная кнопка детекции, обе анализируют ОБОИХ говорящих (не только пользователя):

- **Детектор манипулятивных приёмов (§3.28 ТЗ)** — красный бейдж 🚩 с названием приёма (переход на личности/подмена тезиса/ложная дилемма и т.д.).
- **Разбор расхождений (§3.16 ТЗ)** — три уровня по цвету (🟠 неточность / 🔴 противоречие / 💩 сильное расхождение), с кнопкой «Отметить как заведомую ложь» — только ручное действие пользователя, система никогда не проставляет это сама.

Третья — на уровне проекта, не разговора, отдельный компонент `ArchetypePerspectivesSection.tsx` (тот же паттерн, что `PredictionsSection.tsx`):

- **Взгляд глазами других (§3.11 ТЗ, обе ветки)** — выбор из восьми фиксированных ролей (полицейский/юрист/бабушка у подъезда/финансовый аналитик/психолог/ребёнок/ревнивая жена/скандалист), свой кастомный архетип, ИЛИ реальный человек из проекта (Пункт 46) — для него открывается выбор из уже добавленных людей, не текстовый ввод: промпт строится из его коммуникационного профиля, связей и известных прецедентов, честно предупреждает AI не выдумывать при нехватке данных. Каждая перспектива помечена 🟡 «догадка ИИ».

Четвёртая — на уровне конкретного фигуранта, встроена в `PeopleSection.tsx` рядом с уже существующими Steelman/Source Conflict/Stale Facts, закрывает вторую ветку §3.11, честно отложенную при построении третьей фичи:

- **Коммуникационный профиль (§3.11 ТЗ, ветка "реальные фигуранты")** — шесть наблюдаемых признаков (предпочитает письменную коммуникацию/прямоту/время на решение/реагирует на данные/избегание конфликта/стиль принятия решений), каждый с текстовым описанием источника наблюдения. Кнопка «Обновить профиль» — накопительное обновление: повторный вызов не создаёт дубликат, а обновляет существующую запись на самое свежее наблюдение (upsert на уровне БД).

Пятая — четвёртый источник сверки §3.16, встроена в `ConversationsSection.tsx` рядом с бейджем расхождений:

- **Проверка по ссылке пользователя (§3.16 ТЗ, четвёртый источник)** — вместо автономного AI-поиска (см. обсуждение в `apps/api/prisma/README.md`, «Пункт 40» — почему автономный поиск по человеку не добавлен), пользователь сам вставляет ссылку под конкретной репликой, сервер скачивает именно её и сравнивает. Результат — цветной блок: зелёный (источник подтверждает), красный (противоречит — только этот случай создаёт запись в общей карточке расхождений), серый (источник не даёт ответа).

Шестая — тоже в `ConversationsSection.tsx`, кнопка появляется рядом с кнопкой детекции расхождений после хотя бы одной найденной записи:

- **Выгрузка списка для проверки (§3.16 ТЗ, альтернатива автономному поиску)** — не новый поиск, а выгрузка уже известных приложению данных в пронумерованный текст, который можно скопировать и унести куда угодно (свой поиск, суд, показать кому-то). Формат строки: `{номер}. [{важность}] {говорящий}: «{факт}» ({потенциальное влияние})` — отсортировано по важности (самое серьёзное расхождение сверху, не по порядку реплик в разговоре). ## Тесты (`src/__tests__/`)

Появились впервые в Пункте 33 (`../api/prisma/README.md`). - **`features.spec.ts`** (6 тестов) — выборочно (GET/POST-с-телом на представительных примерах), плюс полное покрытие `uploadConversationAudio()` — единственной функции файла, не использующей `api.ts`-обёртки (стриминг `File` напрямую). Побочный эффект: заодно появилась устойчивость к некорректному JSON от сервера, которой раньше не было вообще.

Закрыто: `PeopleSection.tsx` теперь даёт сменить статус (`<select>` PERSONA/FIGURANT, применяется сразу, `trigger` всегда `'MANUAL'`) и отвязать персону от текущего проекта (кнопка «✕», отдельно стилизована как необратимое действие — не полное удаление персоны и её фактов, для этого по-прежнему нужен Privacy Center).
