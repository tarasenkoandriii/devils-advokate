# Аудит тестов — 2026-08-30

Проверка тестового набора: не «зелёные ли тесты», а действительно ли они проверяют
то, что называют. Скриптами (skip/xit, дубли имён, пустые тела, orphan-спеки,
покрытие вокруг сегодняшних изменений) плюс ручное чтение подозрительных мест.

Итог: **507 jest (было 500) + 667 standalone + 81 TMA, `tsc` чист.**

## Найдено и исправлено

### 1. `legal-disclaimer.service.spec.ts` не проверял реальный вчерашний баг
Существующие тесты использовали `country: "DE"` / `country: "UA"` — двухбуквенные
значения, которые `countryNameToCode()` принимает как уже готовый код через отдельную
ветку (`/^[a-z]{2}$/i`). Тесты проходили и до, и после фикса юрисдикции **случайно**,
не проверяя ничего специфичного для правки. Настоящий баг был именно в обработке
**полного названия** страны («Україна», не «UA») — ни один тест это не воспроизводил.
Добавлены 4 теста: полное название без кода (`"Німеччина"` → `EU`, было бы `OTHER` до
фикса), приоритет `countryCode` над `ipCountryCode`, фолбек на `ipCountryCode` при
полном отсутствии явной страны, честный `null` при отсутствии всех трёх источников.
**Первая версия этого же нового теста сама была неверной** — использовала связку
`UA + INVESTMENT`, а бакет `UA` в `LEGAL_REFERENCE_SEED` пуст **для всех режимов без
исключения** (никогда не исследовался, честная асимметрия §10.4) — тест падал бы
всегда, независимо от корректности кода. Исправлено на `EU + INVESTMENT` (есть MiFID II).

### 2. `telegram-auth.guard.spec.ts` не покрывал вчерашнее изменение вообще
`readVercelIpCountry()` и запись `ipCountryCode` в `user.upsert()` — код, добавленный
вчера в этот же файл — не имели ни одного теста здесь; `jurisdiction.spec.ts` проверял
только чистую функцию `readVercelIpCountry()` в изоляции, не то, что guard реально
передаёт её результат в `upsert()`. Добавлены 3 теста с перехватом аргументов
`upsert()`: валидный заголовок → `ipCountryCode` и в `create`, и в `update`; `XX`/пусто/
мусор → `update` пустой (не перезаписывает старое значение мусором); повторный запрос с
другой страной → обновляется каждый раз, не залипает на первом значении (VPN/поездки).

## Проверено, реальных дефектов не найдено
- Нет `.skip`/`xit`/`test.skip` нигде в наборе.
- Нет пустых тел тестов.
- Нет дублирующихся названий тестов внутри одного файла (два кажущихся совпадения —
  ложные срабатывания regex на подстроки внутри шаблонных строк, не заголовки тестов).
- Нет orphan-спеков (тестов на удалённый сегодня код) — все 9 файлов, не совпавших по
  имени с исходником напрямую, тестируют существующий код под именем, отражающим
  концепцию, а не файл (`jurisdiction.spec.ts` → две функции из двух файлов,
  `feature1-e2e.spec.ts` → сквозной сценарий, и т.д.).
- Каждый сервис с проверкой владения (`assertOwned*`) имеет соответствующий spec-файл.
- Денежная арифметика: сервисные тесты (`dtp-v2`, `family-law-v2`, `health-v2`,
  `investment-group`) намеренно используют круглые числа через fake-Prisma — они
  проверяют логику группировки по валютам, не точность `Decimal`; точность
  `Prisma.Decimal` (0.1+0.2, 100×0.01) изолированно и полно покрыта `money.spec.ts`.
  Разделение уровней тестирования корректно, дублировать не нужно.
- Файлы с малым числом тестов (`retention-classes.service.spec.ts` — 2,
  `ai-engines.controller.spec.ts` — 3 и т.п.) — все оказались тонкими read-only
  обёртками, где 2-4 теста реально исчерпывают поведение, не недостаточное покрытие.
