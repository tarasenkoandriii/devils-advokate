## Исправлено в этом проходе

1. ✅ **CSRF на админке** (был п.1 «Требует решения владельца»).
   SameSite=None-cookie + отсутствие CSRF-токена позволяли cross-site
   form-POST (эксплойт из отчёта: автоформа на
   POST /admin/prompts/…/rollback). В AdminSessionGuard добавлена
   проверка Origin для всех не-safe методов: Origin вне allowlist
   (CORS_ORIGIN) → 403 ещё до чтения cookie; отсутствие Origin
   (не-браузерный клиент) — пропуск, CSRF атакует именно браузерную
   автоотправку, а она Origin несёт. Тест воспроизводит сценарий
   rollback-эксплойта.
2. ✅ **IDOR: acceptShare принимал голый shareId** (был п.5).
   Внутренний cuid — не секрет (мелькает в ответах API/логах). Теперь
   принятие шаринга кандидата требует и токен ссылки из deep-link;
   несовпадение неотличимо от несуществующей ссылки. Изменён контракт
   POST /candidate-shares/:shareId/accept (body.token) — внешних
   потребителей у эндпоинта ещё не было.
3. ✅ **7 FK-колонок без индекса** (недочёт «тест конвенций слеп к
   именованным связям»): AIJob.modelVersionId и fallbackModelVersionId,
   SourceConflict.factAId/factBId (обе с Cascade), conversationId в
   CandidateStageProgress/ComplianceFlag/CandidateFollowUpRequest.
   Найдены скриптовой проверкой всех `fields:[…]` против `@@index`;
   добавлены @@index. Деплой: prisma db push (вместе с таблицами
   job-search).
4. ✅ **Недетерминированный выбор AI-модели**: findFirst по
   AIModelCapability без orderBy — при двух активных capability выбор
   плавал между деплоями. Теперь orderBy createdAt asc («первая
   настроенная выигрывает», смена приоритета — явная деактивация).
5. ✅ **Просроченные AdminSession не удалялись никогда** — таблица
   росла на мёртвых токенах. Оппортунистическая чистка при каждом
   логине (не на горячем пути guard'а); отдельный cron не заводился
   намеренно.
6. ✅ **Админка: 9 await в обработчиках модерации без try/catch** —
   несработавший клик был молчаливым (оператор думал, что одобрил/
   ограничил), а сбой загрузки деталей вешал строку в «Загрузка…»
   навсегда. Все обработчики users/venues/library обёрнуты с выводом
   причины в существующие error-состояния страниц.
7. ✅ **Лендинг, hero-callout «Лжёт или уклоняется?/Выявляет вероятную
   ложь»** — переформулирован во всех трёх языках в «Расходится с
   показаниями?/находит расхождения с предыдущими показаниями и
   документами — выводы делаете вы»: это то, что продукт реально
   делает (discrepancy-analysis), и это снимает прямое противоречие с
   §7.4 продукта и секцией «Честные границы» страницы /jobs. Правка —
   по явному запросу «исправления по аудиту» (прежний текст держался
   на прямом указании — контекст сохранён в комментарии Hero.tsx).

## Перепроверено, оставлено осознанно

- ⚠ **ValidationPipe/class-validator отсутствуют** — DTO по-прежнему
  пустые классы: инъекция Prisma-операторов через query-параметры,
  отсутствие лимитов длины на текст в AI/TTS/БД, 500 вместо 400 на
  невалидных enum. Это сквозной проход по ~всем контроллерам
  (сотни полей) — отдельная задача, не попутная правка.
- ⚠ **Таймауты внешних вызовов и ретраи без бэкоффа** — острота ниже,
  чем на момент отчёта (maxDuration поднят до 60, тела ошибок
  пишутся), но систематического таймаута по-прежнему нет нигде, кроме
  safe-url-fetch. Правильное решение — общий fetchWithTimeout во всех
  клиентах + бюджет ретраев роутера; отдельный проход.
- ⚠ **ESLint + CI отсутствуют; strict:false; спеки вне тайпчека** —
  инфраструктурный проход (37 нерабочих eslint-disable в исходниках
  это подтверждают). Для async-кодовой базы критичен
  no-floating-promises.
- ⚠ **Глобального rate-limiting нет** (включая POST /tts) — в
  serverless in-memory-лимитер бесполезен (каждый инстанс свой);
  честное решение — лимиты в БД по образцу уже существующих дневных
  (Vision OCR 10/сутки). Нужен список защищаемых эндпоинтов от
  владельца.
- ⚠ **jsonMode**: OpenAI-совместимый путь передаёт
  response_format=json_object; Anthropic-путь параметр не передаёт
  (у API нет прямого аналога) — компенсировано validateOutput +
  ретраями роутера. Приемлемо; фиксится промпт-суффиксом при
  необходимости.
- ⚠ **inputHash пишется и не читается** — идемпотентность AI-вызовов
  заявлена в схеме, не реализована. Либо реализовать (кэш по хэшу),
  либо убрать поле — решение продуктовое (повторный вызов может быть
  желателен).
- ⚠ **Три эндпоинта без потребителя** (GET /admin/audit-log,
  /venue-applications/mine, /projects/:id/stale-facts) — оставлены:
  удаление ломает задел под UI, вреда нет.
- ⚠ **Пользовательского соглашения нет** — юридический документ, не
  код.
